# GO-GO Ride

Local transport app for West Bengal: bus search and timetables, arrival alarms, local cars, online games, news.
Live at https://go-goride.com (API at `/api`, app download page at `/`). Android app is live; iPhone is prepared but not built.

## Deploying

- Hostinger Cloud Startup, Node.js web app. It **auto-deploys from GitHub** `supratik-go-go/go-go-ride`, branch `main`, root directory `backend-node`, Node 24.x, entry `server.js`. A push goes live in about 30 seconds.
- **Every push to `main` is live for real users.** Push only finished, tested work, and push server changes and the matching APK together.
- `origin` pushes to both GitHub accounts (supratik0000 and supratik-go-go). Push with `GIT_TERMINAL_PROMPT=0 GCM_INTERACTIVE=never git push origin main --tags`, after `node "go-go-ride apk/scripts/tag-release.mjs"` saves a restore point. `push-to-github.bat` does all three for the owner.
- Live data is the MySQL database from hPanel > Databases, plus uploaded files in `~/gogoride-data/uploads`, never in git. **Deleting the website in hPanel deletes the uploads folder** (this happened on 2026-11-03 and was restored from the owner's backup). After any deploy check https://go-goride.com/api/health (`"database":"ok"`, or the reason it can't connect) and https://go-goride.com/api/stats (14 users and 1,092 buses on 2026-11-25). The server listens first and connects to MySQL right after (Hostinger gives up on slow starts); on the live server it never starts on an empty database.
- hPanel has exactly 10 environment variables: `ENVIRONMENT=production`, `CORS_ORIGINS`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, `CRON_KEY`, and `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE` (the server stops at start without the MySQL ones). Three more come when the owner sets up the SMS phone: `SMS_GATEWAY_USER`, `SMS_GATEWAY_PASSWORD` (the "SMS Gateway for Android" app's Cloud Server section) and `SMS_RECEIVE_NUMBER` (the number people text). Until then sign-up and password changes need no number check and Forgot password points to support; `/api/health` shows `"sms"` (off, ok, or the error). One more for Google sign-in: `GOOGLE_CLIENT_ID` (the "Web application" client ID from the owner's Google Cloud project; the Android client there needs package `com.gogoride.app` and the release key's SHA-1). Until it is set the Google button stays hidden. The values are in `deploy-hostinger-cloud/production-secrets.txt`. Never print or commit them.
- Hosting limits: no inbound WebSockets, idle apps are stopped, one process, 120 seconds per request. So no timers, background work or in-memory state on the server.
- `rollback.bat` (`go-go-ride apk/scripts/rollback.mjs`) goes back to a restore point. An app rollback ships as a new, higher version, because Android won't install a lower one.

## Releasing an app version

The owner releases without Claude by double-clicking `release-app.bat` (logic in `go-go-ride apk/scripts/release-app.mjs`): it asks the version and note, does steps 1 to 3 below, asks YES, refuses secret files, then commits, tags and pushes. The manual steps:

1. Raise `versionCode` and `versionName` in `go-go-ride apk/android/app/build.gradle`, and `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` in `ios/App/App.xcodeproj/project.pbxproj`.
2. Write one line for users in `go-go-ride apk/release-notes.txt`. It appears in the update popup.
3. Run `& 'D:\Go-Go-Ride\go-go-ride apk\build-apk.bat' https://go-goride.com/api` in the Terminal panel. It takes 15 to 25 minutes and copies the APK and `app-info.json` into `backend-node/public/downloads/`.
4. Commit, save a restore point, push. Phones on v1.2 or later show **Update available** (`src/native/UpdatePrompt.jsx` reads `/api/app-version`).

The signing key (`go-go-ride apk/android/keystore/`, `android/keystore.properties`) is git-ignored. Never commit it. Losing it means every user has to reinstall.

## Code

- Server: routes in `src/routes`, logic in `src/services`, game engines in `src/games`. Engine contract: `seats`, `start()`, `turn(state)`, `view(state, seat)`, `move(state, seat, input)`, optional `forfeitWinners(seat)`. All randomness on the server with `node:crypto`; `view()` must never leak hidden cards or trump.
- Database: MySQL, snake_case tables and columns in `mysql/schema.sql` (loaded into an empty database on start by `ensureSchema()` in `src/db.js`). `src/db.js` is async (`all`, `get`, `run`, `insert`, `update`, `byId`, `tx`); `users.phone` is empty for Google sign-ins until the person adds a number. Rows come back camelCased, dates as milliseconds (stored as India time), 0/1 booleans. Raw SQL date parameters go through `at(ms)` or `day(ms)`. `serialize.js` maps the new names back to the old API fields, so replies did not change. New tables (and safe data fixes) go in `mysql/upgrades.sql`, which the server runs on every start, so every statement there must be safe to repeat (`CREATE TABLE IF NOT EXISTS`, `UPDATE ... WHERE ... IS NULL`); `schema.sql` stays the starting design. A change to an existing column needs a careful ALTER there too. Never change existing columns carelessly: the live database already has them.
- Responses use `{ success, message, data, meta }`.
- Server safety net: in `backend-node`, with the test MariaDB running, run `node scripts/api-check.mjs` in the Terminal panel before pushing server changes (826 requests on a fresh MySQL copy of `seed/gogoride.db` in the database `gogoride_check`, clock frozen, compared with `scripts/api-snapshots/`; about 5 minutes). For an intended change, rerun with `--update` and review the snapshot diff. New features get cases in `scripts/api-cases/`. After route changes run `node scripts/api-docs.mjs`. On this PC `npm` is blocked in PowerShell, so call `node` directly.
- App crashes: every screen sits inside `ErrorBoundary` (`components/ui/ErrorBoundary.jsx`, wired in `layouts/Layouts.jsx` and `main.jsx`).
- App: pages in `src/pages`, API calls in `src/services`, Android and iOS code in `src/native`. CSS classes are prefixed per area (`px-`, `own-`, `adm-`, `acc-`, `game-`). Icons come from `lucide-react` only; check them with `node scripts/check-icons.mjs`.
- Match the surrounding code. Comments are sparse and explain why.
